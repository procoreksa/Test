# عقاري — نظام SaaS لإدارة الإيجارات والتحصيلات والفواتير الضريبية

منصة متعددة المستأجرين (Multi-tenant SaaS) لشركات ومكاتب إدارة الأملاك، لإدارة العقارات
والوحدات وعقود الإيجار، متابعة جدول التحصيلات، وإصدار فواتير ضريبية متوافقة هيكليًا مع
متطلبات هيئة الزكاة والضريبة والجمارك السعودية (فاتورة / ZATCA).

## المكدس التقني

- **Next.js 16** (App Router, Server Actions) + TypeScript
- **PostgreSQL + Prisma ORM**
- **NextAuth v5** (Credentials, جلسات JWT) — عزل كامل بين المنشآت عبر `organizationId`
- **Tailwind CSS 4** بواجهة عربية RTL بالكامل (خط Cairo)
- **Recharts** للوحة التحكم، **qrcode** لتوليد رمز الاستجابة السريعة الضريبي

## المزايا المُنفَّذة

1. **تعدد المستأجرين**: كل بيانات المنشأة (عقارات، وحدات، مستأجرين، عقود، فواتير) معزولة
   بحقل `organizationId` على مستوى قاعدة البيانات وطبقة الـ Server Actions.
2. **إدارة العقارات والوحدات والمستأجرين**: تسجيل المباني، الوحدات (سكني/تجاري)، وبيانات
   المستأجرين (فرد أو منشأة لها رقم ضريبي).
3. **عقود الإيجار وجدول الدفعات**: عند إنشاء العقد يُولَّد جدول الدفعات تلقائيًا حسب الدورية
   (شهري/ربع سنوي/نصف سنوي/سنوي/دفعة واحدة).
4. **متابعة التحصيلات**: تتبع حالة كل دفعة (مستحقة، متأخرة، مفوترة، مسددة) مع تحديث تلقائي
   للدفعات المتأخرة.
5. **الفواتير الضريبية (ZATCA-aligned)**:
   - ترقيم تسلسلي لا يتكرر (**ICV**) + رقم فاتورة قابل للقراءة + **UUID**.
   - **سلسلة تجزئة (PIH → Invoice Hash)** تربط كل فاتورة بالتي قبلها لمنع التلاعب بالترتيب.
   - **رمز QR بصيغة TLV** (المرحلة الأولى من فاتورة: اسم المنشأة، الرقم الضريبي، التاريخ،
     الإجمالي، الضريبة).
   - **تصدير UBL 2.1 XML** لكل فاتورة (زر "تنزيل XML" في صفحة الفاتورة).
   - فاتورة **مبسّطة** تلقائيًا للأفراد (B2C) و**قياسية** للمنشآت ذات رقم ضريبي (B2B).
   - احتساب ضريبة القيمة المضافة 15% مع مراعاة إعفاء الإيجار السكني من الضريبة (خاضع فقط
     للوحدات/العقود التجارية، قابل للتخصيص يدويًا).
6. **لوحة تحكم** بمؤشرات الإشغال، التحصيل مقابل المفوتر (آخر 6 أشهر)، والمتأخرات.

### ⚠️ ما يحتاج استكمالًا خارج هذا المستودع قبل الإنتاج الفعلي

الربط الفعلي مع بوابة **فاتورة** (المرحلة الثانية / Integration) يتطلب إجراءات لا يمكن
إتمامها بدون حساب منشأة حقيقي على بوابة الهيئة:

- توليد CSR وتبادله مقابل شهادة **CSID** عبر بوابة ZATCA (Onboarding + OTP).
- توقيع كل فاتورة XML رقميًا (XAdES) بالمفتاح الخاص وتضمين الطابع التشفيري ورمز QR الكامل
  (الحقول 6-9: تجزئة الفاتورة، التوقيع، المفتاح العام، توقيع الشهادة).
- استدعاء `/invoices/clearance/single` (الفواتير القياسية) أو `/invoices/reporting/single`
  (الفواتير المبسّطة) الفعلي.

نقطة التمديد جاهزة في `src/lib/zatca/client.ts` (دالة `submitToZatca`) — حاليًا تُرجع حالة
`PENDING` دائمًا لحين استكمال الاعتماد الرسمي، بدل تنفيذ استدعاء غير آمن بدون شهادات حقيقية.

## التشغيل محليًا

### المتطلبات

- Node.js ≥ 20
- PostgreSQL ≥ 14

### الخطوات

```bash
# 1) تثبيت الحزم
npm install

# 2) إعداد متغيرات البيئة
cp .env.example .env
# عدّل DATABASE_URL ليطابق قاعدة بياناتك المحلية

# 3) إنشاء الجداول
npm run db:migrate

# 4) بيانات تجريبية (منشأة + مستخدم + عقارات + عقود + فاتورة مدفوعة)
npm run db:seed

# 5) تشغيل الخادم
npm run dev
```

افتح `http://localhost:3000` وسجّل الدخول بـ:

- **البريد الإلكتروني**: `admin@demo-realestate.sa`
- **كلمة المرور**: `Passw0rd!`

### أوامر مفيدة أخرى

```bash
npm run build       # بناء إنتاجي
npm run lint        # فحص الكود
npm run db:studio   # واجهة Prisma Studio لتصفح البيانات
```

## النشر على الإنترنت (Vercel + Neon)

هذا هو المسار المُوصى به للنشر بدون سيرفر خاص بك — مجاني للبدء، ولا يتطلب مشاركة أي
باسورد استضافة مع أحد.

### 1) قاعدة البيانات (Neon)

1. افتح [neon.tech](https://neon.tech) وسجّل دخول بحساب GitHub.
2. أنشئ **Project** جديد (اختر أقرب Region لك).
3. من صفحة الـ Dashboard، افتح **Connection Details** وخذ نسختين من رابط الاتصال:
   - **Pooled connection** (فيه `-pooler` في الاسم) → هتحطه في متغير `DATABASE_URL`.
   - **Direct connection** (بدون `-pooler`) → هتحطه في متغير `DIRECT_URL`.

### 2) نشر التطبيق (Vercel)

1. افتح [vercel.com](https://vercel.com) وسجّل دخول بنفس حساب GitHub.
2. **Add New → Project**، واختر مستودع `procoreksa/Test`.
3. تأكد إن الفرع المُختار هو `claude/saas-rental-collections-system-920d12` (أو الفرع
   الرئيسي بعد ما تدمج التغييرات فيه).
4. في خطوة **Environment Variables** ضيف:

   | المتغير | القيمة |
   |---|---|
   | `DATABASE_URL` | رابط Neon Pooled |
   | `DIRECT_URL` | رابط Neon Direct |
   | `AUTH_SECRET` | قيمة عشوائية طويلة (نفّذ `openssl rand -base64 32` وحط الناتج) |

   **لا تضيف** `NEXTAUTH_URL` — Vercel بيظبطها تلقائيًا.
5. اضغط **Deploy** وانتظر (أول مرة بتشمل تشغيل الـ migrations تلقائيًا لإن أمر البناء
   `prisma generate && prisma migrate deploy && next build`).
6. بعد ما ينجح الـ Deploy، هتاخد رابط زي `your-project.vercel.app`.

### 3) تعبئة بيانات تجريبية (مرة واحدة فقط)

من جهازك، بعد ما تظبط `.env` محليًا برابطي Neon (بدل المحليين):

```bash
npm run db:seed
```

⚠️ ملحوظة: أمر البناء بينفّذ `prisma migrate deploy` على كل Deploy جديد (آمن — بيطبّق بس
الـ migrations الجديدة ولا يمسح بيانات)، لكن الـ Seed تنفّذه يدويًا مرة واحدة بس عشان متعملش
بيانات تجريبية مكررة.

## هيكل المشروع (أهم المسارات)

```
prisma/schema.prisma        نموذج البيانات (تعدد المستأجرين، العقود، الفواتير...)
prisma/seed.ts               بيانات تجريبية
src/lib/zatca/               منطق الفوترة الضريبية (VAT، QR TLV، UBL XML، سلسلة التجزئة)
src/lib/actions/             Server Actions لكل الكيانات (CRUD + إصدار الفواتير + الدفعات)
src/lib/schedule.ts           توليد جدول دفعات العقد
src/lib/invoicing.ts          تنسيق إصدار الفاتورة (ترقيم + ضريبة + QR + تسلسل + حفظ)
src/app/(app)/                صفحات لوحة التحكم المحمية (تتطلب تسجيل دخول)
src/app/login/                صفحة الدخول
src/middleware.ts / proxy.ts  حماية المسارات (Next.js 16 proxy convention)
```
